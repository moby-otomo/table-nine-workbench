# Table Nine Script Workbench

A local-first, Markdown-native workbench for developing *Uncles in Space*
Dispatch scripts in the Three-Seat Inquiry format.

## Current Stage

The pilot MVP now covers the full local workflow: create a canonical nine-beat
pilot, develop and audit it, request selected-beat assistance, and build gated
production handoff packages. New pilots begin outside the taxonomy unless a
human supplies a registry number; existing episode IDs, registry numbers, and
filenames are never silently reused.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
```

## Start

```bash
streamlit run src/table_nine/app.py
```

Open `http://localhost:8501/`.

The deterministic mock is the default assistance provider. To use the OpenAI
adapter, configure both values before starting the app:

```bash
export OPENAI_API_KEY="..."
export TABLE_NINE_OPENAI_MODEL="your-selected-model-id"
```

The workbench does not choose a model on your behalf.

## Verify

```bash
pytest
```

The deterministic suite does not use the network and does not require an API
key.

## Project Data

Workbench documents are Markdown files with YAML frontmatter. The structured
frontmatter is authoritative; the Markdown body is a deterministic readable
projection. A body that no longer matches its structured data is rejected
instead of being silently overwritten.

The initial development fixture is:

`04_BIBLIOTHEQUE-des-SCRIPTS/TAXO_No14222-TrafficConeUncle-DispatchWorkbench_UIS_v01.md`

Saving an existing document requires its expected revision. The previous
revision is preserved under `.table-nine-history/` before replacement.

## New Pilots

Use **New pilot** in the sidebar to supply an episode ID, working title and
featured Uncle. The registry number is optional and is never generated by the
workbench. Creation writes a revision-one Markdown document with the standard
nine-beat board and immediately opens it for manual development.

## Script Elements

The beat editor accepts line-oriented performance script elements:

```text
UNCLE_ONE: A dialogue line.
[pause 1.2]
[robot processing 1.5]
[hold on classification card 2.0]
[silence 3.0]
[performance-flexible] UNCLE_TWO: A line open to improvisation.
```

## Assistance Boundary

- Generates hinge alternatives without selecting one.
- Drafts or revises one selected, unlocked beat at a time.
- Keeps machine output visually and structurally distinct until explicit apply.
- Marks applied output as machine-suggested and unapproved.
- Never writes findings, station assignments, or permanent archive additions.

## Editorial Audits

- Human-custody and release-readiness gates.
- Constitutional beat coverage and recurring observation ritual checks.
- Beat and episode pacing against configured targets.
- Audio intelligibility, valid seat identifiers and observable turn-shape checks.
- Locked but unapproved material and factual-claim review markers.
- Read-only diagnostics: audits never apply or save rewrites.

## Production Handoff

- Development packages can be exported from any saved or unsaved working state.
- Table-read packages require a saved working state, all nine beats, the
  selected hinge, closure fields, and a zero-error audit.
- Release packages additionally require approved episode status and explicit
  human approval of the hinge, finding, station assignment and archive addition.
- Packages contain the dossier, structured beat board, performance script,
  archive stub, editorial audit and a checksummed `MANIFEST.yml`.
- The manifest records whether a development package came from saved or unsaved
  work.
- Packaging never publishes to or modifies the permanent archive.

## Known Limitations

- Voice checks are deterministic signals, not semantic taste judgments.
- Factual claims are surfaced for review but not automatically verified.
- The two rotating Uncle identities remain deliberately unassigned.
